# Paid Access 0.1.0-beta.2

The second public beta adds audience segments and page rules for visual
builders and closes two fail-open paths. The EmDash plugin directory remains
unpublished. Source and archives are on GitHub, and the package is on npm under the `beta`
dist-tag; the [verification note](0.1.0-beta.2.md) records the matching digests.

## What's new

- **Audience segments for visual builders.** `Astro.locals.paidAccess.segments()`
  returns `member`, `plan:<slug>` for each owned plan, and `entitled` for an
  entry that may render. A builder's own "Only" and "Everyone except" rules can
  match them without importing this package. The list is `[]` whenever anything
  can't be verified, so paid content fails closed and teasers fail open. See the
  [visual builders guide](../guides/visual-builders.md).
- **Page rules on the Rules page.** **Paid Access Rules → Add a rule for a page**
  adds a members-only rule for a published entry you edit outside EmDash's
  standard editor, such as a page built in a visual builder's own canvas. Page
  rules are people-only and, in stripe mode, need at least one plan.
- **Fail-closed caller plans.** In stripe mode, an access check that requires an
  unknown or removed plan is now denied instead of silently dropping the plan.
- **Route-cache opt-out.** HTML and every other `no-store` response, including
  paid agent Markdown, now opt out of Astro's route cache, so a page hint or a
  broad route rule can no longer replay a paid body to an unpaid request.

## Install

Use a server-rendered EmDash 1.2 site on Node 22.12+ with Astro
`^6.1.3 || ^7.3.5`:

```sh
pnpm add emdash-paid-access@0.1.0-beta.2 @emdash-cms/x402@1.2.0
```

Register the core descriptor and `paidAccessAstro`, then render protected bodies through
`PaidContent`; see the [installation guide](../guides/installation.md).

## Beta scope

Everything in the [0.1.0-beta.1 scope](0.1.0-beta.1-announcement.md#beta-scope)
still applies, including the private/no-store HTML policy. New in this beta and
not yet exercised on a deployed host: `segments()`, its private entitlements
route, and page rules. No visual builder publishes the builder-side entry point
for segments yet; the guide's recipes use placeholder names.

See the [verification note](0.1.0-beta.2.md) for what was checked, what was not
repeated from beta.1, and the known limits.
