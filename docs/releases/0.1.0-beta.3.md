# Paid Access 0.1.0-beta.3 candidate

Prepared October 15, 2026. This is a source and package candidate, not an npm
publication or production release. The legacy Stripe plugin is not a runtime
dependency; its offline records may be migrated only after an explicit review.

## Required host

This candidate requires EmDash core and x402 built from the reviewed fork
revision `ee970858e3dc460c52791ee1f49c348b0818c07a`. Stock registry EmDash 1.2.0
lacks `emdash/reader-access`, `emdash/plugin-payments`, and the paid plugin
HTTP dispatcher. The stock 1.2.0 source qualification failed on these missing
APIs. The existing peer semver range alone does not establish
compatibility. `pnpm check:core` refuses a source release gate without those
exports; the remaining type/runtime checks validate their contracts. The qualified
environment also used the matching fork builds of admin, blocks, plugin-cli and
plugin-test; registry versions of those packages were not qualified here. This
work has not published the required core revision or established a reproducible
installation outside the prepared environment.

The candidate manifest is `private: true` to prevent accidental publication.
Do not publish beta.3 to npm until a supported, installable core dependency
and clean consumer workflow are available. Do not instruct users to install
stock 1.2.0 as a substitute. Core publication needs its own reviewed release.

This image predates the beta.3 version/documentation preparation; it proves the
same runtime implementation, not installation of the final beta.3 archive bytes.
The release delta after `d7f0a07` changes package version/publication metadata,
documentation and release-check scripts; `src/` is unchanged. The external
release report records the final source commit, empty runtime diff and archive

The attended stopped-writer drill checkpointed the synthetic database, restored
a disposable copy, booted both candidate and previous images with networking
disabled, and verified unchanged protected records. The previous staging image
and saved deployment configuration were restored and verified before candidate
cutover.
Both staging volumes and rollback archives/checkpoints remain retained.
Production's service identity, version and specification hash stayed unchanged.

Fresh native sign-in succeeded for three synthetic identities. All 73 subsequent
HTTP checks passed: 44 baseline access/cache checks, 14 after Stripe test-mode
revocation, and 15 logout/replay checks. Public and origin requests verified
entitlement, denial, protected text absent from unauthorized HTML and embedded
JSON, and member-to-anonymous isolation on identical URLs. All 73 checked responses and the three sign-in redemption responses were
`private, no-store`, without a positive cache age or shared-cache hit.

## Release procedure

1. Qualify the exact Site candidate on synthetic-only staging with payments
   disabled, retained image/data rollback, real Stripe test-mode reads and
   member-to-anonymous cache isolation.
2. Run the package release gate with the matching fork, retain the npm-format
   archive and checksum, and record source revision and package contents.
3. Push the reviewed beta.3 source. This does not publish npm or deploy a site.
4. Resolve the core distribution gate, tighten `emdash` and `@emdash-cms/x402`
   peer ranges to the compatible published releases, and verify a clean consumer
   installation. Obtain explicit npm publication approval before removing
   `private: true`. Rebuild and requalify the changed archive. Publish the reviewed archive
   with the `beta` tag, never overwrite an existing version, and verify registry
   bytes and a fresh install. The EmDash registry is a separate release.

## Local qualification mechanism

The qualifying run started with the unchanged frozen pnpm lockfile, then
substituted the existing pnpm symlinks for `emdash`, `@emdash-cms/x402`,
`@emdash-cms/admin`, `@emdash-cms/blocks`, `@emdash-cms/plugin-cli` and
`@emdash-cms/plugin-test` with the corresponding **built** `packages/core`,
`x402`, `admin`, `blocks`, `plugin-cli` and `plugin-test` directories of the
exact fork revision above. The temporary `emdash-plugin` executable wrapper
invoked that fork's built CLI. A `finally` block restored every original link
and wrapper; no `link:` dependencies or local paths were written to the lockfile.

This was the Site's `withForkPeers` qualification helper plus the matching
plugin-test substitution, not a clean registry-only installation. The complete
`release:check` and the 77-test migration audit ran in that environment. The
package checker verified beta.3 in both npm and sandbox manifests and matched
core bytes between them. Consumers must not reproduce this by substituting
stock EmDash 1.2.0. A supported installable core and clean consumer proof are
still publication prerequisites.
